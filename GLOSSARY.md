# AWS Emulator Console

A web console for browsing, changing and calling every service of a local AWS emulator. It exists so a developer can see and drive emulated state without writing SDK code.

## Language

### The emulator side

**Emulator**:
The local process that serves the emulated AWS APIs on one HTTPS endpoint (by default `https://127.0.0.1:9297`).
_Avoid_: LocalStack, backend, server

**Service**:
One emulated AWS API, such as SQS or Kinesis, defined by one Smithy model and built from one service crate.
_Avoid_: client, product, API

**Operation**:
One named action a Service models, such as `SendMessage`.
_Avoid_: command, endpoint, API call (when the definition is meant)

**Operation Status**:
Whether the Emulator does the Operation: Implemented, Scaffolded or Unrouted.
_Avoid_: support level, state

**Scaffolded Operation**:
An Operation the Emulator routes but answers with `501 NotImplemented` because no handler has been written.
_Avoid_: stub, mock, unsupported

**Unrouted Operation**:
An Operation the model declares but the Emulator has no source file for (no `ops/<op>.rs`), so it cannot route it; typically because no scaffold could be generated for it. An Operation listed as skipped that later got a hand-authored file is Implemented, whether or not the skip list was updated.
_Avoid_: skipped, missing

**Source Status**:
The Operation Status read from the emulator source tree when the Catalog was built.

**Observed Status**:
The Operation Status learned from the Emulator's actual answers during a session; it overrides Source Status.

**Coverage**:
How much of a Service the Emulator implements: Implemented Operations out of all its Operations, at one of three Coverage Levels.
_Avoid_: running, health, completeness

**Coverage Level**:
Full when every Operation is Implemented, Partial when some are, None when none are.
_Avoid_: tier, grade

**Availability**:
Whether the running Emulator routes a Service at all, as last learned by a Probe: Available, Absent or Unknown.
_Avoid_: running, enabled, up

**Absent**:
The Availability of a Service the running Emulator answers with "unknown service", meaning that binary does not include it.

**Emulator Credentials**:
The access key pair the Emulator mints on each start and writes to its credentials file; requests must be signed with it.
_Avoid_: test credentials, dummy credentials, root keys

**Reset**:
Returning the Emulator to empty state by restarting its process; it always causes a Credentials Rotation.
_Avoid_: clear, wipe, snapshot restore, delete all

**Credentials Rotation**:
The replacement of the Emulator Credentials that happens on every Emulator start, after which callers holding the old keys are refused.

**Known Issue**:
A recorded gap between a Service's emulated behaviour and AWS, filed under the emulator's `issues/` folder.

### The console side

**Console**:
The browser application a developer uses, together with the Gateway that serves it.
_Avoid_: dashboard, UI, frontend

**Gateway**:
The process that serves the Console on one origin, answers the Console API, and passes AWS requests through to a Connection.
_Avoid_: BFF, proxy (alone), backend

**Console API**:
The Gateway's own JSON interface for catalog metadata, Connections, health and Reset.
_Avoid_: admin API, admin endpoints

**Connection**:
A saved target the Console talks to: one instance of this Emulator, with its endpoint, region, credentials source and client behaviour.
_Avoid_: profile, environment, endpoint (alone)

**Local Connection**:
The Connection the Gateway discovers by itself from the Emulator's files on the same machine; the only Connection in the first release.

**Catalog**:
The compiled, versioned description of every Service and Operation, built from the emulator's own models and source.
_Avoid_: service list, registry, manifest

**Catalog Entry**:
The Catalog's summary of one Service: names, protocol, Category, Tier, Coverage.

**Category**:
One of the 22 groups the Catalog sorts Services into, such as "Application integration".
_Avoid_: section, family, group

**Tier**:
Whether a Service's screens are Custom or Generated.
_Avoid_: level, mode

**Service Module**:
The unit that provides a Service's screens; every Service has one, Generated by default.
_Avoid_: plugin, page, feature

**UI Model**:
The Catalog's per-Service description of Operations, shapes and Resource Types, shaped for building screens.
_Avoid_: schema, spec

### Resources

**Resource Type**:
A kind of thing a Service holds that the Console can list and inspect, such as a Kinesis stream.
_Avoid_: entity, object, model

**Resource**:
One instance of a Resource Type in the Emulator, such as the stream `orders-cdc`.
_Avoid_: item (except DynamoDB items), record, object (except S3 objects)

**Root List Operation**:
The Operation that lists every Resource of a top-level Resource Type without needing another Resource's identifier.

**Describe Operation**:
The Operation that returns the full detail of one Resource from its identifier.

**Child Resource Type**:
A Resource Type whose Resources can only be listed under a parent Resource, such as consumers under a stream.

**Resource Action**:
An Operation offered on a selected Resource, such as Delete or Update shard count.

**Resource Inference**:
Deriving Resource Types from a Service's Operations and shapes when no one has described them by hand.

**Override**:
Hand-written data that corrects or adds to what Resource Inference and the Catalog produced for one Service.
_Avoid_: config, patch, customization (alone)

**Customization Ladder**:
The ordered ways to improve a Service's screens: Inferred, Override, Field Hint, Slot, Custom Module.

**Discovery**:
Calling Root List Operations across Services to count and find the Resources that exist.
_Avoid_: scan (alone), crawl, rescan (except as the button label)

**Probe**:
A single read-only call made to learn a Service's Availability; it never changes state.
_Avoid_: ping, health check (that is the Emulator's own endpoint)

### Screens and calls

**Generated View**:
A Service's resource screens built entirely from its UI Model.
_Avoid_: auto view, default page

**Custom View**:
A Service's screens written by hand for that Service, such as the S3 object browser.
_Avoid_: bespoke page, special page

**API Explorer**:
The screen that runs any Operation of any Service from a form built from its input shape.
_Avoid_: playground, console (alone)

**Operation Form**:
The form the Console builds from an Operation's input shape.

**Snippet**:
The same call rendered as SDK v3 code, AWS CLI, or raw HTTP.
_Avoid_: request preview (alone), code sample

**Call**:
One logical Operation invocation the Console made, with all its retry attempts.
_Avoid_: request (when the whole logical call is meant), API call

**Call Record**:
The captured request, response, timing and outcome of one Call.

**Call Log**:
The session's ordered Call Records.

**Request Inspector**:
The screen that shows and filters the Call Log.
_Avoid_: network tab, logs

**Call Origin**:
Why a Call was made: by the user, by a view, by Discovery, or by a Probe.

**Pinned Service**:
A Service the developer keeps in the sidebar.

**Preference**:
A per-browser choice that is not about reaching the Emulator, such as Pinned Services, accent color, recently viewed Resources and Saved Runs.
_Avoid_: setting (for Connection fields), profile

**Saved Run**:
An Operation and input kept from the API Explorer so it can be loaded and sent again.

## Relationships

- A **Service** has many **Operations**; each **Operation** has one **Operation Status** per **Connection**, where **Observed Status** beats **Source Status**.
- A **Service** has one **Catalog Entry**, one **UI Model**, one **Tier**, one **Category**, and one **Service Module**.
- A **Resource Type** belongs to one **Service**, has one **Root List Operation** (or a parent, as a **Child Resource Type**), at most one **Describe Operation**, and many **Resource Actions**.
- An **Override** belongs to one **Service** and may change any of its **Resource Types** or **Operation Forms**.
- A **Call** targets one **Operation** on one **Connection** and produces one **Call Record**.
- **Discovery** and **Probes** make **Calls**, marked by their **Call Origin**, so they can be hidden from the **Request Inspector**.
- A **Reset** applies to one **Connection** and always causes a **Credentials Rotation**.
- A **Service** has one **Coverage** (from **Operation Statuses**) and one **Availability** (from its latest **Probe**); the two are independent: a Service can be Available with Coverage Level None.
- **Connections** belong to the **Gateway**; **Preferences** belong to one browser.

## Example dialogue

> **Dev:** "Kinesis shows only 45 operations in the API Explorer, but the SDK has 58 commands."
> **Domain expert:** "The Catalog comes from the Emulator's model, so it lists the 45 Operations the Emulator knows. The SDK is newer; its extra commands aren't Operations of this Service yet."
> **Dev:** "And `SubscribeToShard` was skipped by the scaffold?"
> **Domain expert:** "It was, but someone hand-authored it, so its Source Status is Implemented, not Unrouted. If the Docker binary is older and answers 501, the Observed Status becomes Scaffolded for that Connection."

## Flagged ambiguities (resolved)

- The design says services are "running" or "not running". In this Emulator every Service is mounted, so that word was split into **Availability** (does the binary route it) and **Coverage** (how much of it is implemented).
- "Skipped" in the emulator source and "unsupported" in conversation both meant **Unrouted Operation**. A skipped Operation that was later hand-authored is Implemented.
- "Admin endpoint" was used for both the Emulator's `/__admin/health` and the Console's own endpoints. Only the former is an admin endpoint; the latter is the **Console API**.
- "Proxy" was used for both the whole **Gateway** and its pass-through role. Use **Gateway** for the process.
- "Dummy credentials" in the design do not exist here: requests must be signed with **Emulator Credentials**.
